# Open-source Marketplace layout design

## Purpose

Make `codex-handoff` publishable as a GitHub repository that any Codex user
can install from a cloned checkout. The existing personal marketplace remains
a local development convenience only; it is not part of the public contract.

## Repository layout

The repository becomes a Marketplace root:

```text
codex-handoff/
  .agents/plugins/marketplace.json
  plugins/codex-handoff/
    .codex-plugin/plugin.json
    hooks/
    skills/
    tests/
    README.md
    docs/
```

The marketplace manifest names one available local plugin, `codex-handoff`,
with source path `./plugins/codex-handoff`. This is the canonical layout
generated by Codex's plugin scaffolder and makes the source path relative to
the repository marketplace root.

## Public installation contract

After cloning the repository, a user installs it with:

```bash
codex plugin marketplace add <clone-directory>
codex plugin add codex-handoff@codex-handoff
```

The public README will use placeholders instead of author-specific absolute
paths. It will describe hook trust, starting a new task after installation,
the non-destructive first skill check, and the fact that live quota thresholds
are observed during ordinary use rather than forced in an active account.

## Local development contract

The current personal marketplace entry is retained for this machine while
developing. Its plugin source link changes from the repository root to
`<repository>/plugins/codex-handoff`. Code changes require the standard
cachebuster update and `codex plugin add codex-handoff@personal` reinstall.

The repository Marketplace itself is installed locally for the end-to-end
verification. The same repository can therefore be used in two ways:

1. `personal` is a local development entry.
2. `codex-handoff` is the distribution entry that an open-source user installs
   after cloning the repository.

## Migration and validation

Move the existing plugin files beneath `plugins/codex-handoff` without
changing hook or skill behavior. Generate the repository marketplace manifest
with the plugin scaffolder, then restore the existing manifest and content.

Validate the moved plugin with the plugin and skill validators, run the unit
test suite, install the repository Marketplace locally, and confirm that
`codex plugin list` reports `codex-handoff@codex-handoff` as installed and
enabled. The desktop app must use a new task for the first interactive skill
and hook-trust check.

## Non-goals

- No GitHub remote, release, license selection, or automated publishing is
  performed in this migration.
- No daemon, telemetry uploader, automatic session switching, or new hook
  behavior is added.
- The existing V1 behavior and the 3% protective-block threshold do not
  change.
